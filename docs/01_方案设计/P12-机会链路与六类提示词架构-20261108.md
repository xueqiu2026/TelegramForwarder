## 关键边界

1. **重复复用先于AI分析**。相同文字不保证结果可复用：相对日期、回复、相册及媒体上下文可能不同；需核对有效内容、上下文、分析版本和事件归属。复用只添加该条TG消息自己的证据，来源数按不同chat_id及消息发布时间计算，不把转述或上下文本身算成新增来源。
2. **类型仅在门槛之后判一次**。前面的联合分析不选A–F，后面的路由只是按已定类型取模板，不再判一次。有效类型可复用；需AI时批量判定合格事件。类型调用与成稿调用分开计费，不宣称全程只调用一次。
3. **别名服务归一，不证明同一活动**。Fungo/FungoLabs可以关联项目名，但不能靠别名合并不同轮次或凑来源。合并检查只在有误拆候选时执行，不默认全事件再跑一轮AI。
4. **活动流程与阶段变化区分**。同一公告里的获取Box、销毁、换领可合一篇；不同轮次或独立白名单/Mint、后续公告实质改变资格/截止/退款等，应新建关联事件。同一流程出现Mint一词不自动拆开。
5. **编辑不是追加一条新证据**。旧版本证据先失效，再更新归属、36h来源数及关联草稿。文案类型受影响时再判；已发消息的更正、撤回或补发策略是独立待实现项，不能声称库内稿件失效就等于频道原帖已撤回。
6. **截止不等于无关**。已截止仍可归类和生成真实进展；不得作为仍可参与的教程发送。当前发布器只发送main，closed进展尚未打通发布策略；目标图不能当成该能力已上线。
7. **事实与风格分开**。文案只依据明确提供的TG事件资料，X和few-shot仅指导表达。附链不代表已读取网页，关键缺口或实质冲突内部待补；无具体作用的免责声明、缺失字段清单和括号旁白删除。

### 过滤与 AI 判断

当前代码没有关键词硬过滤，不新增“未命中关键词就丢弃”的入口。统一采集原文并存库，适用的完全同文先复用；原文及隐藏链接继续进入同一轮 AI 主题判断与事件归组。以下是 AI 召回线索，而不是代码放行条件：

| 线索 | 示例 |
|---|---|
| 平台 | launchpad、token launcher、meme launch platform、fair launch、发射平台、发币平台、런치패드 |
| 阶段 | coming soon、go live、mainnet、testnet、beta、early access、whitelist、上线、公测、早期准入、런칭、출시 |

AI 要判断平台对象、发行用途、本次具体里程碑或开放安排，以及消息发布时间与当前时间。新平台上线窗口、测试开放预告、早期准入安排可纳入 `verdict=crypto`。预告无需具备尚未开放的操作步骤、价格或奖励。只有泛泛 building/敬请期待而没有具体里程碑，不当作上线预告。

纯生态名单、RPC/域名清单、桥参数、历史复盘、行情份额及争议不能冒充平台上线。只有不可见媒体/链接而无法定性时 uncertain；不能从域名推断平台身份、链、奖励或上线日期。

四种事件必须分开：平台本身上线；平台自身代币销售；平台上的项目发行；已上线平台奖励活动。后三者按原机会范围判断。同平台不等于同事件，另一频道仅提名字、空投或RPC不能给上线事件凑来源。开发阶段、主网开放、后续延期等实质变化分事件；同一已公布上线安排的重复转述可归组。

### 路由与推送

统一TG原文 → 适用同文复用 → 联合AI主题/归组（含别名与近期事件上下文） → 36小时双来源 → 既有判型 → 对应提示词成稿 → 既有发布闸门 → 频道2026。

| 内容对象 | 文案路由 |
|---|---|
| 平台自身上线、测试或早期准入预告 | 新增 launchpad |
| 平台自身卖币、平台内项目出售 | 原 sale |
| 已开放活动的多步实际操作 | 原 tutorial |
| 后续独立延期、取消 | 原 update |

来源门槛仍是同一事件在最近36小时内至少2个不同 `source_id/chat_id`，按消息发布时间跨批次累计；同频道多帖只计一次。单源留内部附录，凑齐后升档。双TG来源是覆盖门槛，不等于官方核验或两份独立调查。

仍在北京时间07:00、13:00、19:00处理和推送，目标仍为2026；复用现有原图选择、分段及发送回执。blocked、已失效预告、来源不足不发送，已有sent记录不重发。过去日期的预告不能仍标preview；没有新状态证据不能推断已上线。开始日期不是活动截止，未给结束时间时 deadline_utc=null。

### 专用文案标准

2026-11-14 用户补充：项目名称、时间和官方社交链接是核心字段，TG资料已确认时必须保留，不能为压缩篇幅删去。

| 字段 | 输出要求 |
|---|---|
| 项目名称 | 规范名称，首段说明平台用途 |
| 开放内容 | 主网、公测或早期准入，不能混同 |
| 时间 | 标明对应阶段；保留已知日期或窗口，时区可靠才换算北京时间，不编具体时刻 |
| 官方社交 | 原文可确认的官方X主页/公告、官方TG入口；不能用采集频道、KOL或聚合号代替 |
| 官网/参与入口 | 有明确依据则提供，与社交链接分开标注 |
| 资格、成本、奖励 | 有依据才写，保留实际限制，不保证获利 |

核心字段缺失记入 context_gaps/internal_notes，不能猜账号、拼网址或将“资料没有”写成“官方尚未公布”。本次补充要求保留已知字段，不新增缺一项便自动拒发的门槛。公开稿不展示内部缺失清单。

先用一两句交代平台做什么、本次将开放什么，再按TG资料密度写日程、开放对象、明确的入口和限制。不强行写教程，不要求读者提前存款、跨链或买币；没有奖励依据不写抢空投。未知非关键字段省略，不列“原文未写”等内部审稿说明。公开稿不出现采集TG名与回链，官方身份可识别的项目入口按原规则保留。
